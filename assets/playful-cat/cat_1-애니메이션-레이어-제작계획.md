## 4. 좌표와 정렬 기준

### 4.1 기준 Canvas

- 모든 위치 계산의 기준은 원본 `1672 × 941 px`이다.
- 원점 `(0, 0)`은 원본 이미지의 왼쪽 위다.
- 원본의 고양이 위치와 배경 구도를 변경하지 않는다.
- 웹 화면에서 원본이 확대·축소되어도 모든 레이어가 같은 비율로 움직여야 한다.

### 4.2 정렬 방식

두 종류의 파일 저장 방식을 구분한다.

1. `cat-scene-clean.png`, `eyes-neutral.png`
   - 원본과 같은 `1672 × 941 px` 전체 Canvas로 저장한다.
   - 정렬 좌표를 별도로 계산하지 않아도 원본 위에 `left: 0; top: 0`으로 겹칠 수 있어야 한다.

2. 꼬리·동공·생선 PNG
   - 불필요한 투명 여백을 제거한 Tight Crop으로 저장한다.
   - 원본 Canvas에서의 위치와 회전축을 `layer-map.json`에 기록한다.
   - Crop 가장자리에는 회전 시 잘리지 않을 만큼 최소한의 투명 여백을 둔다.

### 4.3 반응형 화면 좌표

웹 적용 단계에서는 원본 비율을 유지한 하나의 Scene Stage를 만든다.

```text
scale = max(viewportWidth / 1672, viewportHeight / 941)
offsetX = (viewportWidth - 1672 × scale) / 2
offsetY = (viewportHeight - 941 × scale) / 2
```

- 배경과 모든 레이어는 동일한 `scale`, `offsetX`, `offsetY`를 사용한다.
- 각 레이어가 별도의 반응형 규칙을 사용하지 않게 한다.
- 화면 비율이 바뀌어도 눈과 꼬리가 몸에서 떨어지지 않아야 한다.
- Desktop을 기준으로 검수하고, 좁은 화면에서는 Motion을 정지하는 안전한 Fallback을 사용한다.

## 5. PNG별 제작 명세

### 5.1 `cat-scene-clean.png`

역할:

- 모든 움직이는 레이어 아래에 놓이는 고정 장면이다.
- 고양이 몸, 얼굴, 귀, 수염, 발, 그림자, 자물쇠, 바닥과 자연광을 유지한다.

제거할 요소:

- 파란 생선
- 갈색 태비 꼬리의 움직이는 부분
- 주황색·흰색 태비 꼬리의 움직이는 부분
- 흰 고양이 꼬리의 움직이는 부분

복원 방법:

- 생선이 있던 곳은 주변 바닥의 붓 질감과 빛 방향을 이어서 복원한다.
- 꼬리가 있던 곳은 주변 바닥과 기존 그림자를 참고해 자연스럽게 복원한다.
- 꼬리 뿌리와 몸의 경계는 몸을 다시 그리지 않고, 꼬리 뒤의 바닥만 복원한다.
- 고양이 몸에 닿는 작은 영역은 최대한 좁게 편집한다.

주의:

- 자물쇠는 제거하지 않는다.
- 여섯 눈은 이 단계에서 변경하지 않는다.
- 전체 장면의 색감이나 대비를 재보정하지 않는다.
- 원본과 Clean Scene을 겹쳤을 때 제거 대상 이외 영역에서 차이가 나면 실패다.

### 5.2 `fish-cursor.png`

역할:

- 원본 그림 속 파란 생선을 그대로 사용하는 Custom Cursor다.

제작 기준:

- 원본 생선의 파란색, 흰 테두리, 형태를 유지한다.
- 배경은 완전 투명이어야 한다.
- 가장자리에 회색·베이지색 Halo가 없어야 한다.
- 생선 주변에 원본 바닥 Texture가 섞이면 안 된다.
- Cursor 기준점은 생선 몸통 중앙으로 설정한다.
- 방향 전환은 새 이미지를 만들지 않고 웹에서 수평 반전한다.

### 5.3 꼬리 3개

공통 역할:

- 원본 속 꼬리를 그대로 분리한 투명 PNG다.
- 새로 생성한 단순 꼬리나 다른 무늬의 꼬리를 사용하지 않는다.

공통 제작 기준:

- 원본의 털 결, 무늬, 빛, 그림자 색을 유지한다.
- 꼬리 끝이 잘리지 않아야 한다.
- 꼬리 둘레의 바닥색 Halo를 제거한다.
- 꼬리 뿌리 부분은 몸과 자연스럽게 겹칠 수 있도록 약간의 Feather 영역을 둔다.
- 회전축은 꼬리가 몸 뒤에서 나오는 실제 연결점에 둔다.
- 꼬리가 움직일 때 몸 위로 올라오거나 몸에서 떨어져 보이면 실패다.

파일별 특징:

| 파일 | 원본 위치 | 예상 움직임 | 주의점 |
|---|---|---:|---|
| `tail-brown.png` | 갈색 태비 뒤쪽, 화면 왼쪽 방향 | 가장 작은 폭 | 왼쪽 고양이 몸통 경계와 무늬 연결 유지 |
| `tail-orange.png` | 주황 태비 뒤쪽, 화면 오른쪽 위 | 가장 느린 속도 | 길고 풍성한 털 외곽과 배경 분리 중요 |
| `tail-white.png` | 흰 고양이 뒤쪽, 화면 오른쪽 위 | 중간 속도 | 흰 털과 밝은 배경의 경계가 뭉개지지 않게 처리 |

초기 Motion 값은 다음 범위 안에서 시작한다.

| 꼬리 | 주기 | 회전 폭 | 시작 위상 |
|---|---:|---:|---:|
| 갈색 태비 | 약 `6.8s` | `±2.0~2.5°` | `0s` |
| 주황 태비 | 약 `8.2s` | `±2.5~3.0°` | `-2.1s` |
| 흰 고양이 | 약 `7.4s` | `±2.0~2.8°` | `-4.0s` |

이 값은 고정 명세가 아니라 실제 Layer 연결부를 보고 줄이는 방향으로 조정한다. 눈에 띄는 큰 흔들림보다 “가만히 보면 살랑거리는 정도”를 목표로 한다.

### 5.4 `eyes-neutral.png`

역할:

- 원본에 이미 그려진 여섯 동공을 자연스럽게 덮는다.
- 동공이 없는 상태의 홍채 색, 반사광, 눈 표면을 제공한다.

제작 기준:

- 눈꺼풀, 눈 윤곽, 눈 주변 털은 변경하지 않는다.
- 편집 범위는 각 눈의 홍채 안쪽으로 제한한다.
- 원본 눈의 녹색·올리브색, 그라데이션과 유리 같은 반사광을 유지한다.
- 여섯 눈을 한 번에 전체 재생성하지 않는다.
- 고양이 한 마리씩 두 눈을 완성한 뒤 통합한다.
- 원본 동공의 흔적이나 이중 그림자가 없어야 한다.

### 5.5 눈동자 6개

역할:

- 원본 눈에서 분리한 동공과 필요한 최소 반사광을 담는다.

제작 기준:

- 검은 동공만 기계적인 타원으로 새로 그리지 않는다.
- 원본의 형태, 가장자리 Blur, Highlight와 색 번짐을 유지한다.
- 각 눈마다 별도 PNG로 저장한다.
- 완전 투명 배경을 사용한다.
- 눈꺼풀이나 눈 주변 털을 포함하지 않는다.
- 동공의 이동 중심과 최대 이동 거리를 `layer-map.json`에 기록한다.

초기 이동 한도:

| 고양이 | 수평 최대 이동 | 수직 최대 이동 | 반응 특징 |
|---|---:|---:|---|
| 갈색 태비 | 화면 표시 기준 약 `2~3px` | 약 `1.5~2px` | 몸 방향을 고려해 가장 작게 제한 |
| 주황 태비 | 약 `3~4px` | 약 `2~2.5px` | 세 마리 중 가장 자연스럽게 중앙 반응 |
| 흰 고양이 | 약 `2.5~3.5px` | 약 `2px` | 좌우 눈의 이동량을 미세하게 다르게 조정 가능 |

동공은 생선의 정확한 위치까지 억지로 따라가지 않는다. 화면 끝에 생선이 있을 때는 각 눈의 타원형 이동 한도에서 멈춘다.

## 6. 제작 순서와 승인 Gate

### 단계 0. 원본 동결 및 기록

1. `cat_1.png`의 크기, 파일 용량, Hash를 기록한다.
2. 원본을 읽기 전용 기준 파일로 취급한다.
3. 이후 생성된 어떤 파일도 원본을 덮어쓰지 않는지 확인한다.
4. `cats-base.png`가 새 작업에 연결되지 않았는지 확인한다.

완료 기준:

- 원본 경로와 Hash가 기록되어 있다.
- 사이트 코드 수정은 아직 시작하지 않았다.

### 단계 1. 생선 분리

첫 번째 제작 파일은 `fish-cursor.png`다.

이유:

- 고양이 몸과 겹치지 않아 위험이 가장 낮다.
- 투명 PNG 품질, 원본 색상 보존과 저장 방식을 먼저 검증할 수 있다.

검수:

- 투명 Checkerboard 위에서 가장자리 확인
- 밝은 배경과 어두운 배경 위에서 Halo 확인
- 원본 위치에 다시 겹쳐 차이가 없는지 확인
- 사용자 승인 후 다음 단계 진행

### 단계 2. 갈색 태비 꼬리 Proof

두 번째 제작 대상은 `tail-brown.png`다.

1. 원본 꼬리를 투명 레이어로 분리한다.
2. 꼬리 뒤 바닥을 복원한 부분 Scene을 만든다.
3. 원래 위치에 꼬리를 다시 올려 Neutral Frame을 만든다.
4. `±2°`로 돌린 좌·우 Preview를 만든다.
5. 뿌리 연결부와 바닥 그림자를 검수한다.

이 단계에서 품질이 충분하지 않으면 나머지 꼬리는 만들지 않는다. 추출 방법과 Mask를 먼저 수정한다.

### 단계 3. 갈색 태비 눈 Proof

세 번째 제작 대상은 갈색 태비의 두 눈이다.

1. 두 눈의 Neutral Patch를 제작한다.
2. 원래 동공을 각각 투명 레이어로 분리한다.
3. 중앙, 왼쪽 위, 오른쪽 아래 세 위치의 Preview를 만든다.
4. 이중 동공, 눈 경계 흔들림, 스티커 느낌을 확대 검수한다.
5. 화면 왼쪽 끝을 바라보는 상태에서도 부자연스럽지 않은지 확인한다.

갈색 태비는 몸이 오른쪽으로 향해 있으므로 세 고양이 중 이동 폭을 가장 작게 제한한다. 눈동자가 한계에 도달하면 더 이상 생선을 직접 향하지 않고 자연스러운 곁눈질 상태를 유지한다.

### 단계 4. Clean Scene 완성

갈색 꼬리와 눈 Proof가 승인되면 다음을 진행한다.

1. 주황 태비 꼬리 제거 영역 복원
2. 흰 고양이 꼬리 제거 영역 복원
3. 파란 생선 제거 영역 복원
4. 승인된 갈색 꼬리 제거 영역과 통합
5. `cat-scene-clean.png` 전체 Canvas 출력

원본과 Pixel Compare를 수행해 편집 Mask 바깥 영역이 바뀌지 않았는지 확인한다.

### 단계 5. 나머지 꼬리 제작

1. `tail-orange.png` 제작 및 승인
2. `tail-white.png` 제작 및 승인
3. 세 꼬리를 모두 Neutral 위치에 겹쳐 원본과 비교
4. 서로 다른 주기로 움직이는 짧은 Preview 확인

### 단계 6. 나머지 눈 제작

1. 주황 태비 두 눈 제작 및 승인
2. 흰 고양이 두 눈 제작 및 승인
3. 여섯 Neutral Patch를 `eyes-neutral.png`로 통합
4. 여섯 눈동자의 중심과 이동 한도 기록
5. 생선 위치별 시선 Preview 확인

### 단계 7. Layer Map 작성

`layer-map.json`에는 다음 값을 기록한다.

```json
{
  "canvas": { "width": 1672, "height": 941 },
  "layers": {
    "tailBrown": {
      "file": "tail-brown.png",
      "x": 0,
      "y": 0,
      "width": 0,
      "height": 0,
      "originX": 0,
      "originY": 0,
      "rotationMin": -2.5,
      "rotationMax": 2.5,
      "durationMs": 6800
    }
  }
}
```

실제 숫자는 PNG를 만든 뒤 이미지의 Alpha Bounds와 눈 중심을 측정해 입력한다. 추정값을 먼저 넣지 않는다.

### 단계 8. 정적 합성 검수

애니메이션을 넣기 전에 모든 레이어를 Neutral 위치에 합성한다.

합성 결과는 원본 `cat_1.png`와 거의 동일하게 보여야 한다.

검수 항목:

- 세 꼬리의 뿌리와 무늬가 원래 위치와 일치하는가
- 여섯 눈이 원본과 같은 크기·색·광택을 유지하는가
- 생선 위치와 크기가 원본과 같은가
- 배경 복원 부분에 반복 Pattern이나 번짐이 없는가
- 원본 고양이의 얼굴과 몸이 달라지지 않았는가

Neutral 합성이 원본보다 나빠 보이면 Motion 작업으로 넘어가지 않는다.

### 단계 9. Motion Proof

정적 합성이 승인된 뒤 별도 Preview에서만 Motion을 적용한다.

- 생선: Pointer 위치 추적, 진행 방향에 따라 수평 반전
- 눈: 생선 방향을 향하되 타원형 범위에서 Clamp
- 꼬리: 서로 다른 속도·회전 폭·시작 시점
- 화면 이탈: 생선 숨김, 눈동자는 천천히 Neutral 위치 복귀
- 비활성 Tab: Animation 일시 정지
- `prefers-reduced-motion`: 눈과 꼬리를 Neutral 상태로 고정

### 단계 10. 사이트 적용

이 단계는 모든 PNG와 Motion Proof가 승인된 뒤에만 진행한다.

1. 이전 `cats-base.png` 기반 구현 제거
2. 원본과 승인된 Layer Asset만 연결
3. 자물쇠 위치에 투명한 실제 Button 영역 배치
4. Hover 시 원본을 훼손하지 않는 약한 Glass Overlay만 추가
5. 자물쇠 Click 시 문구 없는 Password Input 표시
6. 입력이 `800ms` 멈추면 Token 검증
7. 실패 시 Input만 비우고 장면 유지
8. 성공 시 Motion 정리 후 기존 Dashboard 표시

## 7. 이미지 편집 방법

### 7.1 기본 방식

- `cat_1.png`를 Edit Target으로 사용한다.
- 투명 레이어는 실제 Alpha Channel이 있는 PNG로 만든다.
- 각 작업은 `precise-object-edit` 또는 `background-extraction` 범위로 제한한다.
- 한 번의 편집에서 여러 고양이나 여러 부위를 동시에 변경하지 않는다.
- 결과는 생성 직후 원본과 비교한다.

### 7.2 AI 편집 사용 범위

AI 편집은 다음 용도로만 제한한다.

- 꼬리나 생선이 사라진 뒤 노출되는 작은 배경 영역 복원
- 원래 동공이 있던 홍채의 작은 영역 복원
- 원본 요소의 투명 배경 Cutout 생성

AI 편집으로 다음을 하지 않는다.

- 고양이 전체 재생성
- 얼굴 재생성
- 눈 전체를 새로운 스타일로 교체
- 꼬리를 새로 디자인
- 전체 배경 교체
- 전체 색감·조명 변경

### 7.3 결정적 후처리

생성된 PNG에는 필요한 경우 다음 후처리만 수행한다.

- Alpha 가장자리의 불필요한 배경색 제거
- 투명 여백 Crop
- 회전 시 잘리지 않도록 투명 Padding 추가
- 원본 Canvas 좌표 측정
- 무손실 PNG 최적화

색상, 형태, 털 무늬를 후처리 과정에서 임의로 바꾸지 않는다.

## 8. 품질 검수 기준

### 8.1 정적 품질

- Neutral 상태에서 원본과 육안상 차이가 거의 없어야 한다.
- `100%`와 `200%` 확대 모두에서 경계 Halo가 없어야 한다.
- 꼬리 뿌리에 틈이나 겹침이 없어야 한다.
- 눈동자가 이동하지 않을 때 원본 눈과 같은 인상을 유지해야 한다.
- 눈 주변에 사각형 Patch 경계가 보여서는 안 된다.
- 동공이 두 개 겹쳐 보이면 즉시 실패 처리한다.

### 8.2 Motion 품질

- 눈동자는 눈꺼풀 밖으로 나오지 않는다.
- 여섯 눈이 기계적으로 완전히 같은 속도로 움직이지 않는다.
- 시선이 흔들리거나 Pointer의 미세 움직임을 그대로 떨림으로 전달하지 않는다.
- 꼬리는 몸에서 분리되어 보이지 않는다.
- 꼬리 그림자가 갑자기 사라지거나 이중으로 보이지 않는다.
- Motion이 장면보다 먼저 눈에 띄지 않아야 한다.

### 8.3 성능과 접근성

- Pointer 이동마다 Layout을 재계산하지 않는다.
- 눈 위치 갱신은 `requestAnimationFrame`에서 한 번씩 처리한다.
- `transform`과 `opacity` 중심으로 Animation한다.
- Token Input과 자물쇠는 Keyboard로 접근 가능해야 한다.
- `prefers-reduced-motion`에서는 움직임을 중지한다.
- 페이지가 숨겨지면 Animation을 중지한다.

## 9. 중단 조건

아래 중 하나가 발생하면 다음 PNG 제작을 중단하고 해당 단계부터 다시 검토한다.

- 원본 고양이의 얼굴이나 체형이 달라짐
- 털 무늬가 원본과 다르게 생성됨
- 꼬리와 몸 연결부를 자연스럽게 만들 수 없음
- 눈동자 분리 결과가 스티커처럼 보임
- Neutral 합성이 원본보다 눈에 띄게 나빠짐
- 투명 가장자리의 Halo를 제거할 수 없음
- 사용자가 해당 PNG를 승인하지 않음

품질 문제를 CSS Blur, 과도한 그림자, 작은 화면 표시로 숨기지 않는다.

## 10. 작업 중 사용자에게 보여줄 결과

각 PNG 제작 단계마다 다음 세 가지를 제공한다.

1. 투명 배경 위의 단독 PNG
2. 원본 위치에 다시 합성한 Neutral Preview
3. 해당 요소만 최소 범위로 움직인 Motion Preview 또는 좌·중·우 상태 비교

사용자는 각 단계에서 다음 중 하나를 결정한다.

- 승인: 다음 PNG 제작
- 수정: 해당 PNG만 다시 제작
- 중단: 원본과 승인된 파일만 남기고 작업 종료

## 11. 첫 실행 순서

계획 승인 후 바로 모든 파일을 만들지 않는다. 다음 순서로 시작한다.

1. `cat_1.png` Hash 기록
2. `fish-cursor.png` 한 개 제작
3. 투명도와 원본 합성 결과를 사용자에게 제시
4. 승인 후 `tail-brown.png` 제작
5. 갈색 꼬리의 Neutral·좌·우 Preview 제시
6. 승인 후 갈색 태비 눈 2개 Proof 제작
7. 여기까지 자연스러울 때만 전체 Scene과 나머지 고양이로 확대

첫 세 단계의 목적은 빠르게 구현하는 것이 아니라, `cat_1.png`의 완성도를 손상하지 않고 실제로 분리 가능한지 증명하는 것이다.

## 12. 완료 정의

다음 조건을 모두 만족해야 레이어 제작이 완료된 것으로 본다.

- 원본 `cat_1.png`가 변경되지 않았다.
- 승인된 Clean Scene, 생선, 꼬리 3개, 눈 바탕, 눈동자 6개가 존재한다.
- 모든 투명 PNG에 올바른 Alpha Channel이 있다.
- `layer-map.json`의 위치와 회전축이 실제 이미지와 일치한다.
- Neutral 합성이 원본과 거의 동일하다.
- 눈과 꼬리 Motion이 과장되지 않고 자연스럽다.
- 사용자 승인 전 사이트의 실제 인증 화면에 연결하지 않았다.
- 실패한 `cats-base.png` 기반 구현을 최종 코드에서 제거했다.
